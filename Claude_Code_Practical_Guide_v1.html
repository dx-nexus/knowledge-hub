Claude Code とは何か
⌨️ Claude Code — ターミナルで動く AI ペアプログラマー

インストール

Claude Code は npm 経由でインストールします。Node.js（v18 以上）が必要です。Anthropic アカウントと API キーの準備もあわせて行ってください。

  • 1
    Node.js のインストール確認
    ターミナルで node -v を実行し、v18 以上であることを確認します。古い場合は nodejs.org から最新 LTS を取得してください。
    node -v # → v20.x.x 以上であればOK
  • 2
    Claude Code のインストール
    npm でグローバルインストールします。
    npm install -g @anthropic-ai/claude-code
  • 3
    API キーの設定
    Anthropic Console（console.anthropic.com）で API キーを発行し、環境変数に設定します。
    # macOS / Linux export ANTHROPIC_API_KEY="sk-ant-..." # Windows PowerShell $env:ANTHROPIC_API_KEY = "sk-ant-..." # 永続化（.bashrc / .zshrc に追記） echo 'export ANTHROPIC_API_KEY="sk-ant-..."' >> ~/.zshrc
  • 4
    動作確認
    プロジェクトディレクトリで claude を実行し、対話が始まれば成功です。
    cd /your/project claude # → プロンプトが表示されればOK

CLAUDE.md — プロジェクト定義ファイル

CLAUDE.md はプロジェクトルートに置くマークダウンファイルです。Claude が毎回読み込み、プロジェクトのルール・構成・禁止事項を把握します。書くほど Claude の精度が上がります。

# CLAUDE.md サンプル ## プロジェクト概要 このリポジトリは〇〇業務の自動化スクリプト群です。 ## ディレクトリ構成 - scripts/ : Python スクリプト - docs/ : HTML 成果物（GitHub Pages 公開） - data/ : 入力データ（git 管理外） ## コーディングルール - Python 3.10+ を使用すること - 文字コードは UTF-8 - コメントは日本語で記述 ## 禁止事項 - data/ 以下のファイルをコミットしないこと - API キーをハードコードしないこと ## デプロイ手順 cd docs && git add . && git commit -m "deploy" && git push
権限モードの使い分け
🟢
通常モード（デフォルト）
危険操作は確認ステップあり
ファイル操作・Git などの重要な操作は Claude が「実行してよいか」を確認してから進みます。初めて使う段階はこのモードが安全です。
推奨：入門期
🟡
--dangerously-skip-permissions
全操作を自動承認
承認ダイアログを省略して自律実行します。スクリプト組み込みや大量処理に便利ですが、意図しない変更のリスクがあります。Git 管理下で使用してください。

よくある失敗パターンと対処法

Claude Code は強力ですが、使い方を誤ると意図しない変更や情報漏洩のリスクがあります。以下のパターンを事前に把握しておくことで、安全・快適に使い続けられます。

プロンプト設計の落とし穴
⚠️
指示があいまいすぎて意図と違う結果が出る
「これを直して」「いい感じにして」のような抽象的な指示は、Claude の解釈が発散しやすく、想定外の変更が加わることがあります。
「〇〇という問題を解決するために、△△ファイルの□□関数を修正してください。変更範囲は該当関数のみ」のように、対象・目的・範囲を明示します。
⚠️
コンテキストが長くなりすぎて精度が落ちる
1 つのセッションで複数の無関係なタスクを続けると、会話履歴が積み重なり、後半の指示の精度が低下することがあります。
/clear でコンテキストをリセットするか、/compact でコンテキストを圧縮します。タスクが変わったら新しいセッションを始める習慣をつけましょう。
⚠️
日本語と英語が混在した指示でブレが生じる
コメントは日本語・コードは英語・指示は混在、という状態では Claude の出力品質がばらつきやすくなります。
CLAUDE.md に「コメントは日本語・変数名は英語・指示は日本語で記述する」と明記してください。指示言語を統一することで再現性が上がります。
セキュリティ・情報管理の落とし穴
🔒
機密情報・API キーをそのまま渡してしまう
本番 API キー・パスワード・個人情報が含まれたファイルを Claude に直接読ませると、会話ログに残るリスクがあります。
.gitignore / .claudeignore で機密ファイルを除外します。環境変数（.env）はサンプル（.env.example）に差し替えて渡しましょう。API キーは必ず環境変数経由で管理します。
🔒
--dangerously-skip-permissions を本番環境で使う
承認ダイアログをスキップするオプションを本番サーバーで使うと、誤った rm・上書き・デプロイが承認なしで実行されてしまいます。
--dangerously-skip-permissions はローカル開発環境・ステージング環境のみで使用します。本番環境では必ず通常モードを使い、重要操作は手動で確認してください。
🔒
社名・個人名・顧客情報が資料に残る
内部資料を元にドキュメントを生成させると、具体的な顧客名・担当者名・社内コードが出力に含まれる場合があります。
公開資料を生成する際は「社名・個人名・顧客情報を含めないこと」を指示に明記します。生成後は必ず人目でレビューを行ってください。
作業効率の落とし穴
💡
承認ダイアログを惰性でOKして意図しない変更を取り込む
「どうせ合っているだろう」と内容を確認せずに承認を続けると、不要なファイル削除・誤ったリファクタリングに気づかないまま進んでしまいます。
承認ダイアログでは必ず diff を確認します。大規模変更は git stash で退避してから実行し、問題があれば git checkout で戻せる状態を維持しましょう。
💡
巨大なタスクを一度に投げてしまう
「このシステム全体をリファクタリングして」のような巨大タスクは途中で迷走したり、部分的に未完了で終わることがあります。
タスクを「ファイル単位」「機能単位」に分割して段階的に指示します。Claude に「まず計画を立ててから実装してください」と前置きするのも効果的です。

PowerShell — 資料生成 + デプロイの自動化例
# deploy.ps1 — Claude Code で HTML 生成 → git push まで自動化 param( [string]$ConfigFile = "config.json", [string]$TargetRepo = "C:/git/hancho-docs" ) Write-Host "=== Claude Code 自動デプロイ開始 ===" -ForegroundColor Cyan # Claude Code でファイル生成 claude -p "@$ConfigFile を読み込み、仕様に基づいて HTML 資料を生成してください。出力先は $TargetRepo にしてください。" # git push Set-Location $TargetRepo git add . git commit -m "auto: Claude Code 生成 $(Get-Date -Format 'yyyy-MM-dd HH:mm')" git push Write-Host "=== デプロイ完了 ===" -ForegroundColor Green
Bash — ログ解析レポートの定期生成例
#!/bin/bash # weekly_report.sh — 週次ログレポートを Claude Code で自動生成 REPORT_DIR="./reports" DATE=$(date +%Y%m%d) # Claude Code でレポート生成（自律モード） claude -p " logs/ ディレクトリの今週のログを解析してください。 ・ERROR / WARN を件数集計（サービス別） ・頻出エラーパターン TOP5 を抽出 ・前週比の増減コメントを付与 結果を ${REPORT_DIR}/report_${DATE}.md として保存してください。 " echo "レポート生成完了: ${REPORT_DIR}/report_${DATE}.md"
MCP サーバーとの連携

MCP（Model Context Protocol）は Claude Code の拡張機能です。Slack・GitHub・データベース・社内 API などのデータソースを Claude が直接参照できるようになり、コンテキストの幅が大幅に広がります。

MCP サーバーできること活用例
GitHub MCPPR・Issue・コードを直接参照「今週の PR レビューまとめて」
Slack MCPチャンネル投稿・検索「このバグ報告を dev チャンネルに投稿して」
Filesystem MCP任意のディレクトリへのアクセス「NAS の設計書フォルダを読んで要約して」
Database MCPSQL 実行・スキーマ参照「先月の売上集計クエリを書いて実行して」
Custom MCP社内 API や独自データソース自社システムとのシームレスな連携
