アプリ vs PowerShell vs WSL vs VS Code — 何で起動するべきか
作成：2026-05-16 ／ 実機検証ベース
🎯 結論
PowerShellから直接起動が安定・最推奨
Windows×日本語環境では、PowerShellでネイティブに claude コマンドを起動するのが最も安定。
アプリ版や WSL 経由は文字化け・シェル混乱・パス問題が起きやすい。
OneDrive配下のフォルダは作業ディレクトリとして使わない。
⚡ 3ルール
ルール理由
① PowerShell から起動Windowsネイティブ・コマンド互換性・文字化け回避
② 作業ディレクトリは C:\git\ 配下OneDriveは同期で消失リスク・パス長制限・ロック競合
③ 起動時に --permission-mode acceptEdits毎回のYes/No確認スキップ・デモ・運用効率化
# 推奨起動コマンド（コピペ用） cd C:\git\hancho-kb claude --permission-mode acceptEdits
🆚 起動環境の比較
💙
① PowerShell から起動
最推奨
起動方法：claude コマンドを PowerShell で実行
メリット：
  • Windowsネイティブ・最も互換性高い
  • PS コマンド（Get-Content, Copy-Item等）が問題なく動く
  • 日本語パス・ファイル名が文字化けしにくい
  • 環境変数・git設定がそのまま使える
デメリット：Linux系コマンド（curl, grep等）の挙動は限定的
💚
② VS Code 内ターミナルから起動
OK
起動方法：VS Code のターミナル（デフォルトは PowerShell）
メリット：
  • エディタ統合・ファイル変更を即確認
  • 複数ターミナル並行起動可
  • git連携が見やすい
注意点：ターミナルのデフォルトシェルが PowerShell であることを確認（設定 → terminal.integrated.defaultProfile.windows）
⚠️
③ WSL（bash）から起動
条件付き
起動方法：WSL ターミナル（Ubuntu等）から claude
問題：
  • PSコマンドが /usr/bin/bash: Get-Content: command not found エラー
  • Windowsパス（C:\...）と Linuxパス（/mnt/c/...）の混在
  • 日本語ファイル名の文字化け（UTF-8 / Shift-JIS問題）
  • Claude Codeが自動でPSにリトライするが時間ロス
使うなら：Linux系の作業に限定。Windowsファイル操作は避ける。
🚫
④ Claude Desktop アプリ内
非推奨
状況：Claude Desktop アプリは MCP（Model Context Protocol）経由でローカルツールを使える仕組みだが、Claude Code とは別物。
問題：
  • 「Working directory no longer exists」エラー（OneDrive同期不安定パス）
  • パス指定・シェル制御がCLIより不自由
  • 長時間タスクで切断されやすい
推奨：Claude.ai は「対話・設計」用、Claude Code は「実装・実行」用と役割分担。
⚠️ よくある問題と対処
症状原因対処
Get-Content: command not found bashシェルで PowerShell コマンドを実行 PowerShell から claude を起動し直す
"追セ蜩。網サ髻「董り" のような文字化け エンコーディング不一致（UTF-8 ↔ Shift-JIS） ファイルは UTF-8 (BOMなし) で保存。PowerShellで $OutputEncoding = [System.Text.Encoding]::UTF8
Working directory no longer exists OneDrive配下フォルダが同期で移動／削除 作業ディレクトリを C:\git\ 配下に変更（OneDrive配下にしない）
毎回 Yes/No 確認が出る permission モードがデフォルト claude --permission-mode acceptEdits または Shift+Tab で auto モード切替
ファイル変更が見えない・遅延 OneDrive同期との競合 OneDrive対象外のパス（C:\git\等）を使う
パスのバックスラッシュエラー Windows と Linux の混在 PowerShellではスラッシュ / でもOK。WSLでは /mnt/c/...
長時間タスクで切断 アプリ版のWebSocket切断 長時間タスクはCLI（PowerShell）で実行
📌 OneDrive 問題の重要度

📌 OneDrive配下のフォルダは作業ディレクトリにしない：
・OneDriveが裏で同期するため、ファイルが一時的に消える/移動することがある
・Claude Codeが「Working directory no longer exists」でセッション中断
・git とOneDriveの二重管理は事故の元
・推奨：C:\git\ 配下にgitリポジトリを置く（OneDrive対象外）

⚙️ はんちょう向け推奨設定
起動方法（毎回これだけ）
# PowerShell を Win+R → "powershell" で起動 # 作業ディレクトリへ cd C:\git\hancho-kb # Claude Code を確認スキップモードで起動 claude --permission-mode acceptEdits
PowerShell プロファイル設定（任意・1回限り）

📌 毎回 --permission-mode acceptEdits を打つのが面倒なら、エイリアスを設定：

# PowerShell プロファイルを開く notepad $PROFILE # 以下を追記して保存 function ccode { claude --permission-mode acceptEdits @args } # 再起動後、`ccode` で起動可能に
エンコーディング設定（文字化け対策）
# PowerShell プロファイルに追記 [Console]::OutputEncoding = [System.Text.Encoding]::UTF8 $OutputEncoding = [System.Text.Encoding]::UTF8 # これで日本語ファイル名・出力の文字化けを抑制
作業ディレクトリ整理（推奨構造）
C:\git\ （Claudeの作業ルート） ├── hancho-kb\ （vault: ナレッジ管理） ├── hancho-docs\ （公開: knowledge-hub） ├── algo-trading-private\ （Algo Trading） └── （今後の新プロジェクト） # OneDrive配下は触らない
