思想：分離された作業箱と疎結合ポータル

隔離ワークスペース管理の重要性：本PoCでは、作業箱を C:\git\pmo-automation\ に完全に独立して作成します。親ディレクトリや既存リポジトリとGitネストを生じさせず、AI処理（大量コンテキスト）の崩壊や依存関係混在を防止します。実務的には以下の利点があります：

  • Gitネスト回避により意図しないコミット範囲拡散を防ぐ
  • VDIやセキュア環境での運用ポリシーに合わせた最小権限導入が可能
  • 障害切り分けが容易になり、監査ログが明瞭化

ポータル疎結合の設計

ツール実行系（実働箱：`pmo-automation`）と人間向けナレッジハブ（`hancho-docs`）は疎結合に保ちます。ポータルはリンクカードで機能を参照するだけに留め、実装変更は実働箱側で完結させる“マイクロサービス的ガバナンス”を採用します。

運用手順（概略）

  1. 端末で `mkdir C:\git\pmo-automation` を作成。
  2. 全作業は `C:\git\pmo-automation` 内で行い、成果物のみ `hancho-docs` のカード経由で参照させる。
  3. リモートは実働箱専用のリポジトリ（例：https://github.com/dx-nexus/pmo-automation.git）を利用する。

モデル・モード選択（最適化の理由）

チャット下部のモデル選択を「Auto（自動）」に設定します。Auto選択は低遅延・高スループットな軽量モデル（例: Claude Haiku 4.5 相当）を優先し、コマンド実行やドキュメント生成のコストと速度のバランスを最大化します。

VS Code の設定（Ctrl + ,）で以下を有効にしてください（管理者承認が必要な組織では事前に申請）：

  • Copilot Terminal: Auto Approval — AIがターミナルコマンドを実行する自動承認（運用上はログ監査を必須化すること）。

初期コマンド（正確に実行）

mkdir C:\git\pmo-automation
cd C:\git\pmo-automation
git init

上記で作成された空箱にスクリプトやトランスクリプトを置き、以降の自律実行はこの箱内のみで完結します。

AIによるタスク分解の例（人は1行指示）

人間指示: "Run PoC generation"

AIが内部で分解して行うタスク（例）:

  1. フォルダ生成: `transcripts/`, `output_minutes/`
  2. ダミー文字起こし 2 本を生成
  3. `minutes_agent.py` を実装（3層出力、クロスチェック、用語DB）
  4. Python 実行テスト: `python minutes_agent.py`

生成物の価値（コンサル品質の解説）

トラブルシューティングとワーキングツリーの掃除

404エラーA：URL誤指定（Pagesの表口/裏口）

間違ったURL（例: https://dx-nexus.github.io/knowledge-hub/ は Pages の公開 URL であり、Git push の対象ではありません）。Git push にはリポジトリの裏口 URL（例: https://github.com/dx-nexus/pmo-automation.git）を使用してください。

404エラーB：権限/公開設定

リポジトリをPrivateで作成した場合、未ログインまたは権限のないブラウザからアクセスすると404になります。Settings → Danger Zone → Change repository visibility でPublic化する手順を実行してください（社内ポリシーとの整合は要確認）。

ワーキングツリーの掃除（例）

AIが一時的に生成した `commit_msg.txt` のようなファイルは追跡せず削除してください：

del /f /q commit_msg.txt

その後、`git status --short` でワーキングツリーがクリーンになっていることを確認します。

リモート連携とハブ統合（コマンド一覧）

リモート登録とPush

リモートの宛先を設定し、mainブランチへPushする標準コマンド：

git remote remove origin
git remote add origin https://github.com/dx-nexus/pmo-automation.git
git push -u origin main

READMEの法則

`PROJECT_TOTAL_SUMMARY.md` を `README.md` にリネームすることで、GitHub のリポジトリトップに内容が自動でレンダリングされます。コマンド例：

git mv PROJECT_TOTAL_SUMMARY.md README.md
git commit -m "docs: rename summary to README for GitHub rendering"
git push
