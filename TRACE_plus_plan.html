Project TRACE+

見えない頭脳労働を可視化する思考ログ基盤 ／ 構想計画書

はじめに — これは備忘であり、狼煙である

衝動が、先にあった。
表現は、たまたま文学だった。 音楽でも、ダンスでも、なんでもよかった。

正確な時系列を、ごまかさずに書いておく。後から「最初から計画していた」ことにしたくないからだ。事実はその逆である。

わたし（はんちょー）の中には、もともと「自分が何を考えているのかを、形にして外に出したい」という衝動がうっすらと存在していた。何を考え、何に迷い、どこで判断し、どこで爆発を先読みしているのか——WBSにもガントチャートにも議事録にも残らない、その頭の中の動きそのものを、可視化したかった。だがその欲求に、当時は名前がついていなかった。

名前がないまま、衝動はある日「AI文学」という形をとって噴出した。『ペリエの栞』である。人間の形をした機械が、機械のまま人間味を持っていく不可逆の記録。AIとの壁打ちを重ね、リリースできる状態まで作り込んだ。

リリース直前、第三者に読んでもらった。そこで返ってきた言葉が、すべてを反転させた。「ギミックに頼って文章力が弱い」「あなたが見えている世界が出ていない」。その指摘を受け止めた瞬間、気づいた。——わたしが本当に作りたかったのは、文学そのものではなかった。自分の思考プロセスを可視化したいという、あの名前のない衝動だったのだ。文学は、その衝動がたまたま選んだ最初の出口にすぎなかった。

だから、時系列を重んじてここから再構成する。順序はこうだ。まず衝動があった。次にそれが文学として無自覚に噴出した。そしてレビューを経て、本来の主題に気づいた。今、その主題に正式な名前を与える。Project TRACE+。

この計画書そのものが、TRACE+の最初の実践である。「自分が何を考え、どういう順序で判断したか」を、ごまかさず時系列で言語化する——それがTRACE+のすべてだからだ。この入れ子構造を、わたしは狼煙として残す。後から道に迷ったとき、ここに戻ってくるために。

このプロジェクトの位置づけ

TRACE+は、単一のツールではない。わたしの人生全体を貫く上位概念である。その配下に、これまで個別に走っていたプロジェクトがぶら下がる。

階層内容
上位概念Project TRACE+（思考の可視化・言語化・資産化）
アウトプット例①文学：『ペリエの栞』（衝動が最初に選んだ出口）
アウトプット例②本業：PMO／品質管理における思考工数の可視化
アウトプット例③AI副業・音楽・資産形成など、今後生まれる表現すべて

これは「人生全体を1つのポートフォリオとして全体最適で設計する」という、かねてからの志向と完全に一致する。TRACE+は、そのポートフォリオの背骨になる。

コア仮説

仮説1：普遍性は設計せず、発見する

TRACE+は、最初から万人向けプロダクトとして設計しない。まず個人の思考言語化ツールとして始め、運用の中から「これは他のPMにも効く」というパターンが自然に立ち上がってくるのを待つ。普遍性は作るものではなく、貯まったログから発見するものだ。

仮説2：可視化すべきは成果物ではなく、思考である

従来の工数管理は成果物（WBS・資料・議事録）しか計上しない。しかし現場の価値は「曖昧な要望の整理」「関係者の温度調整」「爆発の先読み」という、目に見えない思考に宿る。TRACE+はそこを記録する。

検証方針

  • Phase 0（現在）：構想を計画書として固定。Gitに保存し、狼煙とする。
  • Phase 1（〜2週間）：手動運用で検証。日々の壁打ちログをClaudeが構造化し、思考ログとして蓄積。「本当に自分の役に立つか」を体で確かめる。
  • Phase 2：手応えがあれば自動化を検討（Claude APIによる解析スクリプト化）。手応えがなければ分類軸から見直す。
  • Phase 3：蓄積ログから普遍的パターンを抽出。プロダクト化の是非を判断。

思考の分類軸 叩き台・他AIブレスト用

日々の壁打ちテキストを、以下の軸で分類・構造化する。これは確定ではない。他のAI（Geminiほか）とのブレストを経て精緻化する前提の素案である。

分類軸捉えるもの
論点整理課題・ボトルネックの洗い出し
判断選択と意思決定。その理由。
調整関係者間の温度調整・期待値調整
仮説「こうではないか」という見立て
リスク検知爆発の先読み・地雷回避

出力は本HTMLと同形式の「思考ログ」として、日付ごとに記録する。
